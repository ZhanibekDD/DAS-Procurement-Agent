# DAS Снабжение — Procurement Agent MVP

[![tests](https://github.com/ZhanibekDD/DAS-Procurement-Agent/actions/workflows/test.yml/badge.svg)](https://github.com/ZhanibekDD/DAS-Procurement-Agent/actions/workflows/test.yml)

Отдельный внутренний модуль для контролируемых закупок. Он использует существующий
DAS AI как интеллектуальный слой, но хранит проекты, поставщиков, коммерческие
предложения и согласования в собственной базе.

## Что уже реализовано

- проекты и разделы проекта;
- закупочные лоты с подробной спецификацией;
- реестр поставщиков, регионы, категории, рейтинг и признак проверки;
- предварительный просмотр и импорт поставщиков из CSV/XLSX;
- безопасная загрузка PDF/DOCX/XLSX/CSV с хешем от дублей и очередью на AI-разбор;
- подбор существующих поставщиков по региону и категории;
- версионируемые шаблоны запросов КП;
- создание персонализированной рассылки в безопасном `draft_only` режиме;
- обязательное ручное одобрение каждого сообщения;
- регистрация предложений поставщиков;
- сравнение полной стоимости с доставкой, сроком, условиями и рейтингом;
- дисквалификация неполных или несоответствующих предложений;
- журнал действий и API-аутентификация.

Система **не выбирает победителя и не отправляет деньги/заказы автоматически**.
Финальное решение всегда принимает ответственный сотрудник.

## Контур MVP

```text
Проект → Раздел → Лот → Подбор поставщиков → Черновики запросов КП
       → Одобрение → Полученные КП → Нормализация → Рейтинг → Решение человека
```

## Локальный запуск

```bash
cp .env.example .env
# Заменить PROCUREMENT_API_KEY
docker compose up --build
```

Сервис слушает внутренний порт `9200`. Для production его следует публиковать только
через HTTPS reverse proxy и корпоративную аутентификацию.

Проверка:

```bash
curl http://127.0.0.1:9200/health
curl -H 'X-API-Key: change-me' http://127.0.0.1:9200/api/dashboard
```

OpenAPI: `http://127.0.0.1:9200/docs`.

## Импорт поставщиков

Поддерживаются `.csv` и `.xlsx`. Узнаются русские и английские заголовки:

```text
Поставщик | ИНН/БИН | Регион | Email | Телефон | Telegram | Категории | Рейтинг | Проверен
```

Сначала запускается preview без записи:

```bash
curl -H 'X-API-Key: change-me' \
  -F 'file=@suppliers.xlsx' \
  'http://127.0.0.1:9200/api/suppliers/import?commit=false'
```

После проверки — тот же запрос с `commit=true`.

## Политика оценки КП

Текущий прозрачный скоринг:

- полная цена с доставкой — 60%;
- срок поставки — 15%;
- исторический рейтинг поставщика — 15%;
- заполненные условия оплаты — 10%.

Неполное КП или несоответствие спецификации не ранжируется. В следующей версии веса
будут настраиваться по категории закупки и политике компании.

## Что подключается следующим этапом

1. Извлечение разделов и лотов из проектных PDF/XLSX/DOCX через DAS AI.
2. Разбор оплаченных счетов и построение истории цен.
3. Получение ответов и вложений из корпоративной почты.
4. Поиск новых поставщиков по региону через отдельный discovery-процесс.
5. Проверка реквизитов и контактов перед первым обращением.
6. SMTP/Microsoft Graph отправка после одобрения.
7. Telegram/WhatsApp как отдельные каналы после email-пилота.
8. Экспорт сравнительной таблицы и протокола в XLSX/DOCX/PDF.

## Безопасность рассылки

`PROCUREMENT_OUTBOX_MODE` намеренно принимает только `draft_only`. Реальный адаптер
отправки не включён, пока не будут определены корпоративная почта, роли согласования,
лимиты, стоп-лист и политика первого контакта с найденными в интернете поставщиками.
