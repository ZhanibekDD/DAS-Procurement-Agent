# КП из входящей почты

Отдельный процесс `python -m procurement.incoming_mail` проверяет INBOX раз в
минуту, не отправляет письма, не ставит флаг прочтения и ничего не удаляет в
почтовом ящике. Используется тот же защищённый IMAP secret и проверка TLS, что
для копий отправленных писем. SMTP этому процессу не требуется.

Требуется Linux, отдельный контейнер с ограничениями памяти/CPU, общая локальная
SQLite-БД и каталог `/data`. Один kernel flock на этом каталоге исключает двух
одновременных читателей. UIDVALIDITY/UID и SHA исходника предотвращают повторную
обработку. После сбоя проверка продолжается с подтверждённой позиции; повторов
login внутри одной проверки нет. Состояние и задержка видны в «Прайсах и ценах».
Перед чтением ограниченного диапазона SEARCH определяет ожидаемые UID; FETCH
обязан вернуть тот же набор. Неполный ответ не продвигает курсор и повторяется
при следующей проверке, в том числе при удалении письма между командами.

Содержимое общего ящика и оригиналы ещё не проверенных вложений доступны только
администратору с личной сессией. Вложения хранятся отдельно от общего реестра.
Отправитель, тема, HTML письма и ссылки не предоставляют прав, не создают
поставщика и не считаются достоверными реквизитами. HTML и внешние URL не
исполняются и не загружаются. Каждая цена и новая карточка требуют проверки
оригинала и подтверждения человеком; карточка не получает признак «проверен»
автоматически. Известные контрагенты сопоставляются строго по существующей
логике ИНН/email/телефон, конфликты не объединяются.

Лимиты автоматического приёма: письмо 20 МиБ, до 20 вложений PDF/XLSX/CSV,
до 2000 строк на вложение, 25 UID за проход. Приватное хранилище ограничено
1 ГиБ/10000 записей с учётом JSON в базе; ячейка не больше 8000 символов,
предпросмотр не больше 2 МиБ. При свободном месте меньше 1 ГиБ приём приостанавливается
с ошибкой, без удаления данных или продвижения курсора. Письма обрабатываются от начала
папки без молчаливого пропуска старых писем. Большие/многолистовые/повреждённые
прайсы показывают причину и требуют существующего ручного импорта. Непонятные
строки не публикуются. Для неуказанной валюты показывается предупреждение;
подтверждение возможно только для рублей, курс не выдумывается.

После просмотра администратор проверяет общие реквизиты и строки, затем
подтверждает сохранение. Оригинал не изменяется. История цен дополняется,
существующие цены не перезаписываются. Безымянная/непривязанная входящая цена
не назначается автоматически конкретной закупке и не меняет выбранного
поставщика/стадию заказа.
