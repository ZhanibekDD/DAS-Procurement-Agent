# Закупки: границы и проверяемые источники

Заявка и запрос КП — одна закупка с существующим `lot_id`. Старые ID,
строки, вложения, отправленные сообщения и цены сохраняются. Дополнительные
таблицы создаются идемпотентно без удаления старых данных.

## Предпросмотр / отправка

Сервер строит текст из лота и явно выбранных принадлежащих ему `item_ids`.
Предпросмотр фиксирует SHA состава, получателей, шаблона и вложений. Перед
созданием и перед SMTP проверяются принадлежность и неизменность данных.
Браузер не передаёт тело письма. Названный лот «Блоки ФБС» допускает только
24.4.6 — 218 шт, 12.4.6 — 95 шт, 9.4.6 — 128 шт; ПБ блокируется.

По умолчанию подтверждение предпросмотра кнопкой «Отправить запрос» заменяет
отдельный этап согласования. Администратор может включить правило для роли
или суммы. При включённом пороге неизвестная сумма не считается нулём:
требуется отдельное согласование администратором. Старые черновики получают
снимок только после нового явного предпросмотра; старые отправленные записи
не получают задним числом ни подтверждение, ни новую отправку.

Этапы: Черновик → Запрос отправлен → Получены цены → Сравнение →
Поставщик выбран → Заказ. Выбор и заказ — явно записанное решение сотрудника,
не автоматическая оплата или заключение договора. SMTP acceptance не
объявляется подтверждением получения адресатом.

## Прайсы и источники

XLSX/CSV импортируются через сопоставление колонок и подтверждение. PDF
обязательно проходит экран ручной проверки; неизвестные поля не выдумываются.
Для входящего письма используется оригинальный EML с отдельным предпросмотром
каждого XLSX/CSV/PDF-вложения. Отправитель не является доказательством личности
поставщика. Автоматического IMAP polling без настроенного почтового подключения
нет. Система не читает произвольные чужие почтовые ящики.

Карточки сопоставляются по точному ИНН, email или нормализованному телефону.
Конфликтующие идентификаторы не объединяются. Заполняются только отсутствующие
реквизиты. Каждая новая версия прайса добавляет историю, не перезаписывая цену.
Повторный импорт того же источника/листа/строки идемпотентен; изменение уже
импортированного значения требует нового исходника.

Рейтинг надёжности не меняется от цены. Медиана и ценовой индекс рассчитываются
только при наличии минимум двух текущих предложений разных поставщиков с
совместимыми материалом, характеристиками, единицами, валютой, НДС, регионом,
доставкой и минимальной партией. Недостающие условия явно обозначаются.

Расчёт объекта хранит исходный XLSX, SHA, лист и строку. Листы «Итоги»,
«Исходные», «Спецификации», «Источники» образуют функциональную основу карточки.
Явные статусы сохраняются; неизвестный статус не превращается в подтверждённый.
Формулы не выполняются и не заменяются придуманными значениями. Спецификации
отделяются от итогов, чтобы не удваивать количества.

Документы доступны только через существующую серверную авторизацию.
PDF/изображения просматриваются inline; XLSX/DOCX — безопасный просмотр
таблиц/текста без выполнения макросов, внешних ссылок и HTML. Оригинал
скачивается отдельно, включая HEAD/Range. Office-предпросмотр не гарантирует
пиксельное соответствие исходной разметке Word/Excel.

## Проверки

`tests/test_procurement_redesign.py` и `tests/ui_procurement_flow.cjs`
проверяют FBS/SHA/параллельный импорт/legacy/ACL/Range/историю/источники.
Обязателен полный Linux suite с настоящими Poppler/Tesseract, CI, отдельный
canary, SMTP capture без отправки реальным поставщикам, публичный браузер и
репетиция candidate → baseline → candidate на копии БД/файлов. Перед Production
делается новый online-backup и quick_check. Откат возвращает старый container
и image, не удаляет volumes и новые пользовательские данные.
