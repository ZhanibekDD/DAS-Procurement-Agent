# Фактическая отправка КП

Создание записи, подтверждение предпросмотра и sandbox не являются отправкой.
`mail_deliveries` / `outbox_messages`: draft/approved → queued → sending → sent
только после финального SMTP DATA 250. `sent` означает приём SMTP, а не доставку
получателю. Доставка остаётся `unconfirmed` до отдельного подтверждения провайдера.

Адресат один на запись КП: RCPT должен быть принят до DATA. При отказе SMTP или
ошибке подключения до DATA состояние failed, доступен ручной подтверждённый
повтор неизменённого запроса. Message-ID, согласованный fingerprint и MIME
сохраняются. Захват операции выполняется транзакцией BEGIN IMMEDIATE; параллельный
повтор блокируется. При обрыве во время/после DATA до финального ответа состояние
unknown: автоматический и ручной resend запрещены, потому что ровно-однократный
SMTP невозможно гарантировать при потерянном ответе. Оператор сверяет Message-ID
с провайдером. Никаких бесконечных retry.

Полный MIME кодируется потоково на диск, атомарно/exclusive сохраняется в
закрытом `mail-spool/<message_key>.eml` и не перезаписывается. Тот же оригинал
передаётся SMTP и потоковым IMAP APPEND, без чтения всего 100-МБ вложения в память.
Журнал содержит envelope, время, Message-ID, ответ DATA, принятых получателей,
SHA вложений/MIME, результат копирования и аудит попыток. Private пути/credentials
не выдаются в API. Нельзя создавать ложный положительный ответ при отказе.

IMAP использует TLS с проверкой сертификата. `PROCUREMENT_IMAP_HOST/PORT/TLS`,
опциональные USER/PASSWORD_FILE; по умолчанию переиспользуется SMTP credential
(ключи/пароль не меняются). Sent определяется по special-use `\Sent` или явно
администратором через `PROCUREMENT_IMAP_SENT_FOLDER` (ASCII/modified UTF-7).
Нет создания произвольной папки. До APPEND выполняется поиск по Message-ID.
После потерянного ответа APPEND допускается только SEARCH reconciliation: нельзя
добавлять потенциальную вторую копию. Повтор копии никогда не вызывает SMTP.

Если копирование не прошло, показывается:
«SMTP принял письмо, но копия в “Отправленных” не сохранена».
Старая запись без MIME/receipt не дополняется вымышленным SMTP-ответом и никогда
не отправляется повторно ради появления в Sent. Аддитивные таблицы не меняют
исторические строки; rollback на прежний образ сохраняет данные и новые журналы.

Релиз: свежий online-backup БД и файлов/Compose/config, quick_check, Linux/CI,
canary с реальными SMTP/IMAP сокетами, затем отдельное контролируемое письмо
самому настроенному отправителю через существующий провайдер. Сверить Message-ID
в системе/INBOX/Sent и SHA исходного вложения, проверить безопасный повтор
при недоступном SMTP, auth/CSRF, миграцию всех старых строк и фактический rollback.
Не использовать действующих поставщиков для тестов.
